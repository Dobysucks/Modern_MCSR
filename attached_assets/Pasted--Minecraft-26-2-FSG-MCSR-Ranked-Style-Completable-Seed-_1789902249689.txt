# Minecraft 26.2 FSG + MCSR Ranked-Style Completable Seed Filter
## Fabric Mod — Local Filtering + Atum Integration + Standardized RNG

Build a complete Fabric mod for **Minecraft Java 26.2** that recreates the useful gameplay concept of FSG + MCSR Ranked filtered seeds, but implemented natively for Minecraft 26.2.

This is NOT a copy of MCSR Ranked itself.

Do NOT implement:

- Elo
- matchmaking
- online Ranked matches
- player ranking
- accounts
- remote seed servers
- competitive matchmaking

The goal is:

> **FSG-style local seed filtering + Atum reset workflow + MCSR Ranked-style seed requirements + MCSR Ranked-style standardized RNG + a completable-run validator, all running locally in Minecraft 26.2.**

---

# 1. CORE WORKFLOW

The normal user workflow MUST be:

```text
Player launches Minecraft
        ↓
FSG-style UI
        ↓
Choose seed type / filter profile
        ↓
Atum resets world
        ↓
Our mod intercepts the new seed
        ↓
Local background seed filtering begins
        ↓
Generate/analyze candidate 26.2 world
        ↓
Check Overworld requirements
        ↓
Check lava access
        ↓
Check Nether requirements
        ↓
Check standardized RNG progression
        ↓
Check completion viability
        ↓
REJECT or ACCEPT
        ↓
If rejected → immediately continue searching
        ↓
If accepted → give seed to Atum
        ↓
Atum starts the accepted world
        ↓
Player plays
```

The player should NOT normally need to type:

```text
/speedrun filter
```

or manually enter seeds.

The primary experience must feel like **FSG integrated into Atum**.

The mod should automatically search for seeds in the background and feed an accepted seed into the reset workflow.

---

# 2. LOCAL FILTERING

The filtering system must work locally.

Do NOT require:

- an internet connection
- a remote seed API
- a remote seed database
- downloading a predetermined list of seeds

The mod should generate candidate seeds locally and analyze them.

Use asynchronous/background worker threads.

Minecraft's render/client thread MUST NOT freeze while searching.

Architecture should resemble:

```text
SeedSearchManager
    ↓
CandidateSeedGenerator
    ↓
WorldgenAnalyzer
    ↓
SeedFilter
    ↓
LavaPoolAnalyzer
    ↓
NetherAnalyzer
    ↓
RNGAnalyzer
    ↓
CompletionValidator
    ↓
AcceptedSeed
```

# 11. MODERN 26.2 LAVA SYSTEM

This is one of the most important features.

We need:

```text
usable surface lava access
```

not old 1.16.1-specific:

```text
magma ravine
```

requirements.

For every seed type:

### STEP 1 — SEARCH FOR REAL LAVA

Analyze actual 26.2 terrain for naturally generated surface lava pools.

A qualifying natural lava pool must:

- contain real lava source blocks
- be exposed to the surface
- be accessible
- be practically usable for a speedrun portal
- not require ridiculous excavation
- not be completely submerged
- not be inside an unusable cave
- be within the configured search radius

Use actual generated blocks/world state.

Do NOT fake natural pools in the analyzer.

---

# 12. ARTIFICIAL LAVA POOL FALLBACK

If:

```text
No qualifying natural lava pool exists
```

BUT:

```text
The seed passes the other required conditions
AND
the seed is otherwise completable
```

then generate:

```text
EXACTLY 3 ARTIFICIAL LAVA POOLS
```

near the relevant starting location.

Default maximum distance:

```text
32 blocks
```

The three pools must be generated within approximately 32 blocks of the relevant start/structure.

This fallback applies to:

```text
Village
Shipwreck
Desert Temple
Ruined Portal
Buried Treasure
```

---

# 13. ARTIFICIAL POOL DESIGN

Artificial pools should look and behave like plausible Minecraft surface lava pools.

Do NOT create:

- giant lava lakes
- floating lava
- random lava towers
- enormous flat rectangles
- obviously artificial structures
- pools inside important structures

Each pool should:

- be on/near the surface
- have a usable shape
- contain real lava source blocks
- have safe surrounding terrain
- be reachable
- allow portal construction
- be visually similar to a plausible vanilla lava pool

Create:

```text
ArtificialLavaPoolGenerator
```

with:

```text
findCandidatePositions()
validateTerrain()
selectThreePositions()
generatePool()
verifyPool()
```

---

# 14. ARTIFICIAL POOL DETERMINISM

Artificial pools MUST be deterministic.

Same:

```text
World Seed
RNG Seed
Seed Type
Filter Configuration
```

must produce the same:

```text
pool locations
pool dimensions
pool shape
```

Never use uncontrolled:

```java
Math.random()
```

Use deterministic seed-derived RNG.

---

# 15. DO NOT ACCEPT A BAD SEED JUST BECAUSE YOU CAN GENERATE LAVA

The artificial lava fallback is NOT permission to accept any seed.

The correct logic is:

```text
Candidate seed
    ↓
Check structures/resources
    ↓
Check Nether
    ↓
Check RNG
    ↓
Check completion
    ↓
If all pass:
    if natural lava exists:
        use natural lava
    else:
        generate 3 artificial pools
    ↓
ACCEPT
```

If the seed fails another important requirement:

```text
REJECT
```

Do not rescue a bad seed merely by adding lava.

# 19. PIGLIN BARTERING

This is critical.

Use the documented Ranked-style behavior.

Current Ranked documentation specifies:

- Obsidian barter chance increased by approximately 35%
- At least 6 Obsidian guaranteed every 72 barters
- Exactly 3 Ender Pearl trades guaranteed every 72 barters
- Same trade order for players using the same RNG seed

Implement this deterministically in 26.2.

Do NOT simply give the player unlimited pearls/obsidian.

Do NOT arbitrarily force every possible loot item.

The goal is:

```text
standardized + reproducible + viable
```

not:

```text
free loot
```

---

# 20. "PIGLINS MUST PROVIDE WHAT IS NECESSARY"

Interpret this carefully.

The requirement is:

> An accepted Completable seed must have a viable progression under the standardized Ranked-style RNG system.

This does NOT mean:

> Force Piglins to give whatever item the player wants.

Instead:

```text
Seed Filter
+
Standardized Piglin RNG
+
Completion Validator
```

The validator should know what deterministic bartering outcomes the player will receive.

If the intended route requires pearls, the standardized sequence must provide the documented pearl opportunities.

If obsidian is needed, the standardized sequence must provide the documented obsidian guarantee.

Do not invent additional Ranked guarantees.

# 36. IMPORTANT DISTINCTION

```text
1. SEED FILTER
```
